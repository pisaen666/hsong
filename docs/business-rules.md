# กติกาเศษสตางค์ของยอดโอนในแอป Hub2U

เอกสารนี้อธิบายว่าทำไมบางครั้งยอดเงินที่ลูกค้าต้องโอนถึงไม่ใช่ตัวเลขกลมๆ (เช่น ฿220 ตรงๆ) แต่กลับมีเศษสตางค์แปลกๆ ต่อท้าย (เช่น ฿220.47) เขียนให้คนที่ไม่ใช่โปรแกรมเมอร์อ่านเข้าใจ อ้างอิงจากโค้ดจริงในไฟล์ `app.js` และบันทึกงานในไฟล์ `CLAUDE.md`

## 1. เศษสตางค์นี้ "บวกเพิ่ม" อย่างไร

- เกิดขึ้นเฉพาะตอนลูกค้าเลือกจ่ายด้วย **พร้อมเพย์** หรือ **โอนผ่านธนาคาร (SCB)** เท่านั้น
- **ไม่เกิดขึ้น** กับการจ่ายแบบ **เก็บเงินปลายทาง (COD)** — ออเดอร์ COD จะแสดงยอดเต็มเป็นบาทตรงๆ ไม่มีเศษสตางค์
- วิธีคิด (ในโค้ดเรียกฟังก์ชันนี้ว่า `generateUniquePaymentAmount`):
  1. เอายอดรวมของออเดอร์ (ตัดเศษทิ้งถ้ามี เหลือแต่บาทเต็ม)
  2. **สุ่มตัวเลข 2 หลักท้าย (สตางค์) ขึ้นมาใหม่ทุกครั้งที่มีออเดอร์** โดยสุ่มได้ตั้งแต่ **.11 ถึง .98** (ไม่มีทางได้ .00 หรือ .01-.10 หรือ .99-.100)
  3. เอาเศษสตางค์ที่สุ่มได้ไปบวกกับยอดบาทเต็ม กลายเป็นยอดที่ต้องโอนจริง
- เป็นการ **สุ่มใหม่ทุกออเดอร์** ไม่ใช่เรียงลำดับหรือใช้ตัวเลขคงที่ ดังนั้นแต่ละออเดอร์จะได้เศษสตางค์ไม่ซ้ำกัน (หรือซ้ำกันได้โดยบังเอิญ เพราะเป็นการสุ่ม แต่โอกาสน้อย)

## 2. ใช้เศษสตางค์นี้ไปทำอะไร

ใช้เป็น **"ลายเซ็นเฉพาะตัว" ของแต่ละออเดอร์ เพื่อให้ทีมงานฮับตรวจสอบได้ง่ายว่าเงินเข้าจริงหรือยัง**

เหตุผลที่ระบุไว้ในตัวแอปเอง (ข้อความที่ทีมงานฮับเห็นตอนตรวจสลิป):
> "ตรวจสอบสลิปและเปรียบเทียบยอดมีเศษสตางค์ในแอปธนาคาร เพื่อให้มั่นใจ 100% ว่าได้รับเงินจริง"

อธิบายง่ายๆ คือ: แอปนี้ยังไม่ได้เชื่อมต่อกับธนาคารโดยตรง (ไม่มีระบบเช็คอัตโนมัติว่าเงินเข้าแล้ว) ทีมงานฮับจึงต้อง **ตรวจด้วยตาตัวเอง** โดยเปิดแอปธนาคารดูการแจ้งเตือนเงินเข้า หรือดูรูปสลิปที่ลูกค้าแนบมา แล้วเทียบตัวเลขว่า **ตรงกับยอดที่มีเศษสตางค์นี้เป๊ะๆ หรือไม่** — ถ้าแต่ละออเดอร์มียอดเป็นบาทกลมๆ เหมือนกันหมด (เช่น หลายออเดอร์รวมแล้วได้ ฿220 พอดี) ทีมงานจะแยกไม่ออกว่าเงินที่เข้ามานั้นเป็นของออเดอร์ไหน แต่พอมีเศษสตางค์สุ่มติดอยู่ท้ายยอด แต่ละออเดอร์จะมียอดที่ไม่ซ้ำกัน เทียบแล้วรู้ทันทีว่าใช่ออเดอร์นี้

**หมายเหตุ:** โค้ดในส่วนนี้มีคอมเมนต์ชื่อ "Unique Decimal Satang" (เศษสตางค์เฉพาะตัว) ซึ่งสนับสนุนคำอธิบายข้างต้น แต่ไม่มีบันทึกที่ระบุเหตุผลเชิงธุรกิจอื่นเพิ่มเติม (เช่น เรื่องภาษี หรือเหตุผลอื่น) — **ไม่ทราบเหตุผลอื่นนอกจากนี้**

## 3. ลูกค้าเห็นยอดนี้ตรงไหนในแอปบ้าง

ลูกค้าจะเห็นยอดที่มีเศษสตางค์ (ไม่ใช่ยอดกลมๆ) ในจุดต่อไปนี้:

1. **หน้าชำระเงินตอนเช็คเอาท์** — หน้าต่าง QR พร้อมเพย์ และหน้าต่างโอนผ่าน SCB จะโชว์ยอดที่ต้องโอนแบบมีทศนิยม 2 หลัก (เช่น ฿220.47) พร้อมปุ่ม "คัดลอกยอดโอน" ที่คัดลอกตัวเลขแบบมีเศษสตางค์ไปด้วย
2. **หน้าติดตามสถานะออเดอร์ (Tracking)** — ช่อง "ยอดรวม" จะโชว์ยอดที่มีเศษสตางค์ พร้อมสถานะว่า "⏳ แนบสลิปแล้ว/รอตรวจยอด" หรือ "✓ เงินเข้าแล้ว"
3. **ข้อความแจ้งเตือนทาง LINE** หลังสั่งซื้อสำเร็จ — มียอดเงินที่มีเศษสตางค์ระบุไว้เช่นกัน
4. **ใบเสร็จที่พิมพ์ได้ / ใบเสร็จออนไลน์** — ก็แสดงยอดแบบมีเศษสตางค์เหมือนกัน

## 4. ถ้าลูกค้าโอนยอดไม่ตรง (เช่น โอนปัดเศษเป็นบาทกลมๆ) จะเกิดอะไรขึ้น

**สำคัญ: ระบบนี้ไม่มีการเช็คอัตโนมัติ — เป็นการตรวจสอบด้วยมือของทีมงานฮับทั้งหมด** ไม่มีโค้ดส่วนไหนเปรียบเทียบยอดเงินที่โอนจริงกับยอดที่ระบบตั้งไว้แบบอัตโนมัติ (เพราะแอปไม่ได้เชื่อมต่อ API ธนาคาร)

ขั้นตอนที่เกิดขึ้นจริงมีดังนี้:

1. ออเดอร์จะถูกตั้งสถานะเป็น **"รอยืนยันยอดโอน" (pending_verification)** ทันทีที่ลูกค้ากดสั่งซื้อ (ไม่ว่าจะโอนถูกหรือผิดยอด — ระบบยังไม่รู้)
2. ออเดอร์นี้จะไปโผล่ในรายการ **"ออเดอร์ที่รอยืนยันยอดโอนเข้าบัญชี"** บนหน้าจอของทีมงานฮับ พร้อมกล่องเตือนสีส้มให้ "ตรวจสลิปก่อนปล่อยงาน"
3. ทีมงานฮับเปิดดูรูปสลิปที่ลูกค้าแนบมา (หรือเปิดแอปธนาคารดู Noti เงินเข้า) แล้วเทียบกับยอดที่ระบบตั้งไว้ (ยอดที่มีเศษสตางค์) **ด้วยตาตัวเอง**
4. ถ้ายอดตรงกัน → ทีมงานกดปุ่ม **"✅ ยืนยันเงินเข้าบัญชีแล้ว"** → ออเดอร์เปลี่ยนสถานะเป็นยืนยันแล้ว ลูกค้าเห็นสถานะเปลี่ยนเป็น "✓ เงินเข้าแล้ว"
5. ถ้ายอดไม่ตรงหรือดูน่าสงสัย → ทีมงานกดปุ่ม **"สลิปไม่ถูกต้อง"** → ออเดอร์ถูกทำเครื่องหมายว่า "ถูกปฏิเสธ" และระบบจะแจ้งให้ทีมงานติดต่อลูกค้าเพื่อขอหลักฐานการโอนใหม่ (มีปุ่ม "โทรหาลูกค้า" ให้กดโทรได้ทันทีจากหน้านี้)

**ข้อควรรู้เพิ่มเติม (เพื่อความตรงไปตรงมา):**
- การ "รอยืนยันยอดโอน" เป็น **ขั้นตอนเตือนทางธุรกิจ/ระบบงาน ไม่ใช่ตัวล็อกระบบแบบบังคับ** — ไม่พบโค้ดที่ปิดกั้นไม่ให้ทีมงานฮับจัดของหรือจ่ายงานไรเดอร์ต่อแม้ออเดอร์จะยังไม่ถูกกดยืนยันยอดเงิน การยืนยันยอดเงินเป็นเพียงป้ายสถานะเตือนบนหน้าจอ ไม่ใช่ตัวบังคับห้ามทำงานต่อ
- ถ้าลูกค้าจ่ายแบบ **COD (เก็บเงินปลายทาง)** กฎเรื่องเศษสตางค์นี้ไม่เกี่ยวข้องเลย เพราะ COD ใช้ยอดเต็มบาทตรงๆ และถือว่า "ยืนยันแล้ว" โดยอัตโนมัติตั้งแต่ต้น (ไรเดอร์เก็บเงินสดปลายทางแทน)
